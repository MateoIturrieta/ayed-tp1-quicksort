El rango de trabajo

Dos índices delimitan qué se ordena

En cada llamada, Quicksort trabaja sobre un rango entre bajo y alto.

  • bajo marca el primer elemento del rango.
  • alto marca el último elemento del rango.
  • El rango se achica en cada llamada recursiva.
Vector de ejemplo
bajo = 0 … alto = 6
Paso 1

Elegir un pivote

El criterio es fijo: el pivote siempre es el último elemento del rango.

  • Siempre es vector[alto]: no se elige al azar.
  • Todo lo demás se compara contra este valor.
Se toma vector[alto] pivote
Paso 2

Particionar el vector

Se recorre de bajo a alto − 1, comparando cada elemento con el pivote.

  • Si es menor o igual al pivote, se intercambia hacia la izquierda.
  • Los elementos chicos quedan juntos al principio.
  • El pivote todavía no se mueve.
Antes de recorrer
Después de recorrer pivote sin mover
Paso 3

Ubicar el pivote en su lugar final

Se intercambia con el primer elemento mayor que él.

  • Desde ahí, el pivote queda fijo.
  • Ya está en su posición del vector ordenado: no se vuelve a mover.
Se intercambia con el primer mayor
Pivote en su posición fijo
Paso 4

Repetir, recursivamente

Con el pivote fijo, se aplica lo mismo a cada lado, por separado.

  • La mitad izquierda se ordena como un vector aparte.
  • La mitad derecha, como otro.
  • Cada una tiene sus propios bajo y alto.
El pivote fijo separa dos partes

quicksort(izquierda) ← fijo → quicksort(derecha)

Corte de la recursión

¿Cuándo termina?

Cuando el rango queda vacío o con un solo elemento.

  • Es decir, cuando bajo ya no es menor que alto.
  • Un solo elemento ya está ordenado.

Condiciones para usarlo

Qué necesita el vector

Para aplicar Quicksort así, se tienen que cumplir dos requisitos.

  • Elementos comparables: números, o textos en orden alfabético.
  • Acceso por índice, algo que un vector permite.

Cierre · Conclusión

    
Si mañana tuviéramos que ordenar datos reales…

    

      
Muchos datos desordenados→Usamos QuicksortO(n log n) y sin vector extra

      
Datos que suelen venir ordenados→Elegimos otro métodocon el pivote al final cae en O(n²)

      
No sabemos cómo vienen→Quicksort con pivote al azarasí se evita el peor caso

    

    

      
8.000 datos desordenados0,01 s · 119.081 comp.

      
8.000 datos ya ordenados3,19 s · 31.996.000 comp.

      
en nuestras pruebas≈ 310× más lento

    

    
El mismo código puede ser muy rápido o muy lento: depende de cómo lleguen los datos.
